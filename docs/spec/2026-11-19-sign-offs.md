# Sign-offs

**Status:** Implemented 2026-11-19 (phase 1). A1 and A2 passed on Claude Code.
Codex surfaces stay `unsupported` until their own acceptance run; the skill
body is already harness-neutral.

## Outcome

An agent that needs a decision on visual or item-by-item material publishes a
temporary review page. The reader opens one link, picks a choice per item,
adds notes, and copies one structured reply back. Where the page is published
comes from the user's own setup — a local folder, a folder an existing web
server serves, or the bundled server — never from a hard-coded host.

Long-lived documents remain `preview`'s job; the two skills share only the
config file.

## Components

| Piece | Role |
|---|---|
| `skills/solopreneur/sign-offs/scripts/signoff.py` | Publisher: settings, page checks, wrapping, transport, read-back |
| `skills/solopreneur/sign-offs/scripts/server.py` | Store (`store`), HTTP server (`serve`), service installer (`install`); self-contained |
| `skills/solopreneur/sign-offs/assets/page.html` | The review UI every page is wrapped in |
| `skills/solopreneur/sign-offs/assets/strings.json` | `en` and `zh-Hant` dictionaries for the UI, the reply keywords, and the index/expired pages |
| `src/solopreneur/shared/config.schema.json` | The `signoffs` block of `.solopreneur.json` |

## Contracts

### Store

Every provider writes through the same `store` routine, so ids, revisions,
expiry and swaps behave identically everywhere:

- Layout: `<dir>/<id>/` holds the page files plus `meta.json` and `meta.js`;
  `<dir>/.incoming/` stages uploads; `<dir>/.lock` serializes writes.
- A request is a tar of `request.json` and `payload/`. Only regular files with
  no dot-named segment are accepted; `meta.json` and `meta.js` are reserved;
  every file must match the manifest's SHA-256; the payload is capped at 30 MB.
- The id (`<slug>-<3 random characters>`) and the revision are assigned under
  the lock. An update keeps the id and `createdAt`, adds one to the revision,
  and restarts `expiresAt` (`ttlDays`, 1–365). An expired page cannot be
  updated. A failed swap restores the previous revision; if the restore fails
  too, the previous revision stays in `.incoming/`, out of the upload sweep's
  reach, and the error names the folder to move back by hand.
- Only a directory whose `meta.json` names it is ever served, replaced or
  deleted: a store may share a folder with other content, and ordinary names
  match the id pattern.
- Static and local stores rewrite `index.html` on every write and refuse to
  overwrite one without their generator marker.

### Transport

The publisher calls `store` in-process when the target's `host` is this
machine. Otherwise it sends `server.py`'s own source and the request over
`ssh -o BatchMode=yes` to a `python3 -c` loader, so the writing code is always
the publisher's version; the host needs only `python3` 3.9+. A host counts as
this machine when its user matches, `ssh -G` shows neither another port nor a
jump host, and the host name `ssh -G` resolves (the name as written only when
ssh cannot resolve it) is one of this machine's whole names or addresses; a
wrong guess is caught by the read-back. A `host` is limited
to letters, digits and `. _ - @ :` and may not start with `-`, `--` ends ssh's
options, and the connection forwards no agent, X11 or ports, so a repository's
own config cannot inject ssh options or shell syntax. The host runs
`python3 -I`, so files in the login directory cannot shadow standard modules.

### Page

- The agent writes a content fragment; a whole HTML document is refused unless
  `--raw`. Item ids must be present, unique, free of spaces (a reply line
  starts with the id), and on `<section>` elements. Choice labels, folded as
  the page folds them, cannot contain ` — `, which starts a reply line's note.
  The checks read attributes from the parsed tags, quoted or not.
- The publisher wraps the fragment in `page.html` in one pass (tokens inside the
  content stay as written); the template carries the publish's content id in
  `<meta name="signoff-content">`. A `--raw` page is published untouched.
- The page reads its metadata from `meta.json` over http(s), and from
  `meta.js` (`window.SIGNOFF_META`) under `file://`, where browsers refuse
  `fetch()`.
- The page refuses review when its content id differs from the metadata (a
  reload during an update), when item ids repeat, and once `expiresAt` has
  passed — the only expiry guard for `local` and `static`, so a `--raw` page
  must stop building replies at `expiresAt` itself.
- Choices are saved in the reader's browser per id, revision and content id,
  so an id issued again after removal or expiry starts empty. A choice label
  wrapped across lines is folded onto one, keeping one decision per reply line.
- Reply: first line `sign-off <id> r<revision>`, then one line per decided
  item (`<id> <choice>[ — <note>]`), `<id> <not-chosen> — <note>` for a note
  without a choice, a pending list, and an overall comment. Keywords follow
  `lang`.

### Read-back

The printed link is fetched first, as the reader opens it, and compared with
the `index.html` that was sent: a web server that serves `<id>/index.html` but
refuses the folder address `<id>/`, or redirects it to another path (a host
that strips trailing slashes, so the page would load `meta.json` and its images
from the parent folder), fails; a redirect to another scheme or host on the
same path is fine. Every published file and `meta.json` are then fetched
relative to where the link landed, as the page loads them, and compared with
what was sent. Any mismatch or fetch failure exits 3 and withholds the
link. The fetches carry no credentials, so `url` cannot sit behind a login
page: pages stay private by being served on a network that only the readers
and the publishing machine reach, such as a tailnet or a VPN. The read-back
cannot see a reader's browser cache, and an update keeps its file names: a
`static` folder must be served without long-lived caching, so an update's
images are fetched again.

### Server

`serve` binds to loopback only and answers `Cache-Control: no-store` on every
response. It serves only pages with valid metadata, never dot paths,
directory listings, or a file a symlink leads outside the store (a folder's
own `index.html` included), answers 410 for expired pages, renders the index per
request, redirects `/<id>` to the relative `<id>/` (sub-path proxies keep
working), queues 128 pending connections (an HTTP/2 proxy opens a dozen at
once), and deletes expired pages every hour. `install` copies the server and
its dictionary to a stable directory, writes a launchd agent or systemd user
unit, and prints — never runs — the commands that (re)start it and the
`tailscale serve` line. The store refuses to work through a symlinked `.incoming`,
`.lock` or `.index.html.tmp`.

Configuration rules — resolution order, path rules, cross-feature handling of
the shared file — are in `src/solopreneur/shared/config.md`, "The `signoffs`
block".

## Out of scope (phase 1)

A Vercel provider; a submit button that writes the reply back; publishing from
agent gateways; Codex publication.

## Acceptance

### A1 Contract and regression suite

Accepted 2026-11-19. `scripts/tests/test_signoffs.py` (67 tests, run by
`validate-plugin-packages.yml` on Python 3.9 and 3.14, Linux and macOS)
passed on Python 3.14.6 and the macOS system Python 3.9.6. It covers page
checks (including a `--raw` page loading `meta.js`, folder links, a named
pipe, `srcset` URLs holding commas, CSS `@import` and uppercase `URL(` read
from style elements and attributes but never from prose or CSS comments, item
ids with spaces, choice labels holding ` — `, and a page over the cap refused before it
is read), wrapping, the dictionary
(including the verbatim `zh-Hant` wording) and its match with the schema,
settings resolution per block (explicit, walk-up, user level, broken files,
invalid values and provider rules in any target, a `url` with a query, a fragment or no host,
linked worktrees, submodules), host detection
(whole names only; forwarded ports and jump hosts are other machines), `host`
values that would reach ssh as options or shell syntax, length limits checked
before anything is written, all three providers end to end against temporary directories and
loopback HTTP servers, the shipped-source SSH path (the exact remote command
run through a local shell), the printed update command keeping `--target`,
read-back failures including an unreadable `meta.json` and a link redirected
to another path (exit 3), files read back from the host a link is redirected to, an existing `.gitignore` that did not ignore the pages (a `*` with a trailing tab included) or is a symlink, a folder holding other
files (another tool's `.lock` included), expiry and pruning (other files in `.incoming` stay), store refusals (symlinked bookkeeping entries, a request cut short, over-long source
details clipped instead), concurrent updates, the swap rollback (and a failed
restore keeping the previous revision, even past the upload sweep), every server response
rule including a folder whose `index.html` links outside the store and the 40-connection burst, and `install`.

Preview's suite gained three cases for the shared file (a user-level file with
only `signoffs` is stepped over unvalidated; an explicit one still fails for
preview; a malformed `signoffs` block fails a file preview reads) and passed 498 of 500 with the two
existing host-filesystem skips.

### A2 Claude Code

Accepted 2026-11-19 on Claude Code 2.1.328 (Opus 5.5), macOS, from this
session's shell:

- **local:** a page published from a linked worktree landed in the main
  working tree's `docs/solopreneur/sign-offs/` with a `*` `.gitignore`; one
  update kept the URL and `createdAt` and moved the revision to 2. Driven in
  headless Chrome over `file://`, the page read `meta.js`, built the controls,
  and composed `sign-off <id> r2` with a choice, a note-only item, the pending
  list and a two-line overall comment. With `expiresAt` moved into the past the
  page refused review and disabled the reply button; updating it was refused;
  the next publish deleted it and dropped it from `index.html`.
- **static:** published into a folder served by `python3 -m http.server`; the
  read-back matched, `meta.json` carried no source details, and the index kept
  its generator marker. The first attempt ran while that server was still
  starting and exited 3 without printing a link, as designed.
- **server:** `server.py serve --lang zh-Hant` on a temporary store, targeted
  through a config naming this machine as `host` (written locally, no SSH).
  The read-back matched; responses carried `no-store`; `/<id>` redirected to
  `<id>/`; the index and page wording matched the maintainer's current
  `zh-Hant` pages, and the composed reply used `通過`, `未選`, `未批：`,
  `整體：`. A mismatched content id blocked review with the reload message.
- **install:** into a sandbox home it copied the server, wrote the launch
  agent with `/usr/bin/python3`, printed the start and `tailscale serve`
  commands, and warned that the requested port was already taken.
